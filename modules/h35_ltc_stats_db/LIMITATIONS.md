# H35 長照與居家醫療統計資料庫 (`h35_ltc_stats_db`) 局限與待突破清單

> **目的**：明確標示目前 `ltc.db` 的資料邊界、統計粒度與技術局限，防止 AI 在分析時產生過度推論（幻覺），並作為後續資料擴充與突破的行動指南。

---

## 一、資料粒度與分析局限 (Data & Analytical Limitations)

1. **健保居家醫療缺乏「病人端」申報明細**
   - **現況**：`ltc_homecare_providers`（來自 `opendata_39331`）僅包含參與「居家醫療照護整合計畫」的**院所與整合團隊名單**（5,147 筆）。
   - **局限**：無法直接計算健保居家醫療在各 CMS 失能等級、年齡層或疾病別的實際收案人數與就醫次數，也無法直接比對「同一位病人是否同時使用健保居家醫療與長照 2.0」。

2. **專業服務 (`C` 碼) 未細分至 `CA`～`CD` 子碼與職類**
   - **現況**：1966 統計報表（`11_pro_service`, `18`, `19`）僅統計到 `C` 碼整體使用人數。
   - **局限**：無法從現有 `ltc.db` 區分物理治療 (`CA`)、營養/吞嚥 (`CB01`/`CB02`)、環境評估 (`CC`) 與護理指導 (`CD02`) 的個別人次需求與職類缺口。

3. **時間粒度以「年度」為主（僅費用申報為「月度」）**
   - **現況**：絕大多數 1966 報表為年度累積（民國 110～114 年），僅 `15_city_claims`（費用申報）為單月統計（`period: 114-01 ~ 114-12`），`opendata_124999`（新北市長照特約單位）為單季彙總快照（1 筆）。
   - **局限**：無法進行月度季節性波動分析（例如冬季/流感季對居家醫療與喘息服務的即時影響）。

4. **部分指標表僅抽取首欄數值至 `metric_value`**
   - **現況**：`ingest_city_metrics_pdf` 將表格第 1 個有效數字存入 `metric_value`，其餘欄位（如涵蓋率 `%`、各類機構細項）存於 `attributes_json.values` 陣列。
   - **局限**：次要欄位尚無法直接透過純 SQL 欄位進行跨表排序或聚合，需搭配 JSON 解析。

5. **1966 報表 `(二)` 與 `(十四)` 尚未入庫**
   - **現況**：`02_target_group_users.pdf`（原住民/身障/失智）與 `14_disabled_cms_users.pdf`（身障者 CMS 等級分布）屬於多層跨欄特殊版面，目前尚未納入 `cli.py build`。

## 二、待突破方向 (Breakthrough Roadmap)

| 優先序 | 突破目標 | 具體可行路徑 |
| :---: | :--- | :--- |
| **P0** | **補齊 `C` 碼子類 (`CA`～`CD`) 與職類人次** | 搜尋政府資料開放平臺或衛福部長照司統計年報，尋找「長照專業服務各細碼申報人次」CSV/XLSX 資料集。 |
| **P1** | **完成 `02` 與 `14` 報表解析入庫** | 擴充 `etl.py` 支援特殊族群（身障、失智、原住民）與 CMS 交叉表解析。 |
| **P1** | **多欄指標具名展開 (`ltc_coverage_workforce_stats`)** | 將 `CITY_METRIC_SPECS` 升級為多欄映射，讓「涵蓋率 %」、「通過金額 (千元)」等次要欄位也能直接成為獨立可查詢指標。 |
| **P2** | **串接貫通健保居家醫療 × 長照 2.0 病人端串聯** | 規劃向衛福部衛生福利資料科學中心（HWDC）申請去識別化串聯檔，驗證重度失能者（CMS 7～8 級）在宅醫療與長照的實際重疊與缺口。 |
